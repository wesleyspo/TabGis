TabGis Platform

Ajuda do utilizador e referência técnica

Plataforma web para utilities (energia, telecomunicações, águas, gás, etc.) com mapa operacional, basemap vectorial em PostGIS/GeoServer, fundos raster em MBTiles e painel de operação. Esta página resume a interface, o modo online versus offline e aponta para a documentação Markdown do repositório.

Fontes: docs/mds/Escopo_Projeto_TabGis.md, docs/mds/CONTEXT_STATE.md, docs/mds/GeoSampa_offline_operacao.md, docs/mds/GeoSampa_offline_tecnico.md.

1 O que é o TabGis

Solução TabGis: gestão e visualização de redes técnicas com reforço de same-origin na plataforma (nginx na porta 8088 a servir frontend e proxies para /geoserver, /tiles e /api).

Esta página é servida também em GitHub Pages (cópia estática). O link «Voltar ao mapa» abre o index.html da mesma origem; em ambiente local use o URL do teu servidor (:8088).

2 Stack tecnológica

Componentes open source usados na plataforma (detalhe de portas e SQL em docs/mds/CONTEXT_STATE.md).

PostGIS PostgreSQL 15 GeoServer WMS/WFS SLD versionados TileServer GL MBTiles / SQLite nginx Docker Compose Node.js / Express Leaflet MongoDB Playwright

Dados e mapas

  • PostGIS — schemas landbase (feições IBGE/OSM, municípios-alvo, bairros, vias), config, security, audit, operations, ref, gis, oms, mwm, schematic (unifilar), events (diário de integração), topologia nativa tabgis_utilities_topo e segmentos lineares da rede em gis.network_span — ver TOPOLOGY_NATIVE_POSTGIS.md.
  • GeoServer — workspace base_sp, camadas WMS/WFS, GetFeatureInfo, estilos em infra/geoserver/styles/.
  • TileServer GL — MBTiles raster (satélite SP, GeoSampa) via /tiles/.

Aplicação e integrações

  • Frontend — HTML/CSS/JS (frontend/index.html, main.js, styles.css), tipografia Inter.
  • API — traduções, utilizadores e RBAC, ordens e folha OMS, geocodificação, tipos ref.*, equipas, agregados OMS, auditoria, rotas demo MWM, vistas esquemáticas (/api/schematic/*), metadados e segmentos lineares com leitura e edição (GET/POST /api/topology/spans, GET/PATCH/DELETE /api/topology/spans/:id), GET /api/events e export cursado GET /api/events/export.
  • Serviços externos (online) — tiles Esri World Imagery, Nominatim, Open-Meteo, RainViewer (radar).
  • MongoDB — reservado a eventos / event_report (evolução futura).
  • Playwright — testes E2E em e2e/.

3 Funcionalidades online e offline

«Offline» aqui significa sem depender da Internet para servir dados ao browser, desde que a stack Docker e os volumes locais (PostGIS, MBTiles, nginx) estejam disponíveis na rede onde acede ao :8088. A geração de alguns MBTiles ainda pode exigir WMS GeoSampa online durante o build.

Área Online Local / offline
Imagem de fundo Satélite Esri (XYZ), requer Internet no cliente. Satélite MBTiles (sp_satellite), GeoSampa MBTiles (geosampa_offline) via TileServer; toggles mutuamente exclusivos com o online.
Vectorização — UF, municípios, vias, alvos e bairros via WMS/WFS no próprio GeoServer (dados em PostGIS).
Busca por endereço Nominatim (OSM) com viewbox em SP. Geocodificação local por substring em landbase.vias_alvo_sp com unaccent (sem número de porta).
Clima (TMP) Open-Meteo (previsão), RainViewer (radar) — requer Internet. —
i18n / admin Google Fonts (CDN) no carregamento da página. Traduções e CRUD leve via API contra PostGIS; utilizadores security.users.

4 GeoSampa offline (MBTiles)

Ortofoto PMSP em MBTiles (geosampa_offline.mbtiles), servida pelo TileServer atrás do nginx em /tiles/. O cliente activa «GeoSampa - Offline» depois de verificar saúde do dataset (ver checkLocalRasterHealth em main.js).

Guia operacional

Resumo de GeoSampa_offline_operacao.md — o que correr no servidor e como validar no mapa.

  • Pré-requisitos: Docker Compose (infra/docker-compose.yml), serviços db, tileserver, web; espaço em disco (pacote completo pode ter dezenas de GB).
  • Gerar (primeira vez ou recriar): na raiz do repo, ./infra/scripts/build_geosampa_offline_mbtiles.sh — pode demorar muitas horas; depois docker compose -f infra/docker-compose.yml restart tileserver (e web se o nginx resolver mal o hostname tileserver).
  • Reparar buracos (tiles em falta): ./infra/scripts/repair_geosampa_offline_mbtiles.sh; opcional DELAY_MS, WMS_MAX_ATTEMPTS; em background com nohup conforme o runbook.
  • Validar: http://<servidor>:8088/ → Camadas → GeoSampa - Offline; pan/zoom na área de SP.
  • Respeitar termos de uso GeoSampa / PMSP (uso académico / POC).
Referência técnica

Resumo de GeoSampa_offline_tecnico.md — ficheiros, env e semântica de falhas.

  • Scripts: build_geosampa_mbtiles.py, wrappers shell, repair_geosampa_mbtiles.py (só chaves ausentes na tabela tiles).
  • data/tiles/config.json — registo TileServer geosampa_offline.
  • Env típicos: MBTILES_OUT, BBOX, ZMIN/ZMAX, WMS_BASE/WMS_LAYER, DELAY_MS, TIMEOUT_SEC, retentativas, REPAIR_COMMIT_EVERY.
  • MBTiles: tabela tiles (zoom, column, row, PNG); convenção de linha Y invertida (função flip_y_to_mbtiles_row no Python).
  • Fonte HTTP: WMS raster.geosampa.prefeitura.sp.gov.br, GetMap EPSG:3857.
  • Build: contador fail para pedidos sem PNG válido; o processo pode continuar se ok > 0. Reparação: fail após retentativas sem inserção.
Markdown completo no GitHub (branch main): GeoSampa_offline_operacao.md · GeoSampa_offline_tecnico.md

5 Satélite local (MBTiles Esri → raster)

Pacote sp_satellite.mbtiles (capital SP, zoom típico 10–17), gerado por infra/scripts/build_sp_satellite_mbtiles.sh. O frontend consulta /tiles/data/sp_sat.json antes de activar o toggle; após alterações no contentor TileServer, reiniciar tileserver e web (resolução de DNS interna Docker no nginx — ver CONTEXT_STATE).

404 de tiles fora da bbox é esperado (cobertura parcial). minNativeZoom / maxNativeZoom estão alinhados ao pacote instalado.

6 Topbar, mapa e zoom (%)

Layouts da interface (esquema)

Com o botão Operação activo, a app usa a classe has-left-panel no contentor .app. O interruptor ao lado (rótulo i18n «Foco no centro de controlo (~75 %)») alterna entre app--oper-layout-split (metade / metade) e app--oper-layout-ccc (grelha 2×2 com mais área para o painel). A topbar decorativa mostra só Mapa em tela cheia; com Operação aberta, os títulos Centro de Controle e Mapa alinham-se às colunas no modo split (ver docs/mds/CONTEXT_STATE.md — topbar 60px).

Estes blocos são diagramas (cores e proporções alinhadas à POC), não substitutos de capturas de ecrã reais. Para material gráfico futuro, podem acrescentar-se PNG/WebP em frontend/assets/help/ e referenciá-los aqui com <img>.

Esquerda

  • Início — repõe a vista inicial (inset diferente em tela cheia vs. painel Operação 50/50).
  • Operação — abre ou fecha o painel lateral; opção de layout conforme configuração.

Direita

  • Estado — feedback curto (carregamento, erros, confirmações).
  • Clima — atalho (ícone sol + nuvem) para a guia TMP.
  • Busca — municípios e bairros (WFS); endereço (Nominatim ou PostGIS local).
  • Camadas — fundo raster (online / satélite local / GeoSampa offline), vias, limites, municípios-alvo, bairros; pills OMS/MWM/GIS/LAND.
  • Rede técnica — «Segmentos lineares da rede» (camada WMS base_sp:v_network_span_wms): traçados de gis.network_span com topologia nativa PostGIS; edição via POST/PATCH/DELETE /api/topology/spans (arquivo pré-delete em auditoria e eventos gis.topology.network_span.*).
  • Configurações — idioma, visualização, utilizadores, tipos ref, traduções, esta ajuda.

Só um menu entre Busca, Camadas e Configurações fica aberto; clique fora da topbar fecha os painéis.

Mapa

  • Camadas vectoriais WMS (GetFeatureInfo ao clique).
  • Limite UF e lógica municípios-alvo / bairros em função do zoom (limiar ~12; configurável em «Gerenciar visualização»).

Indicador de zoom (%)

0 % = baseline da última vista Início; 100 % = detalhe máximo do raster activo (ou do mapa sem raster). A partir de ~50 %, a app pode activar automaticamente bairros e vias quando o zoom Leaflet o permitir.

7 Busca

  • Município / bairro — listas WFS; ao escolher bairro, enquadramento do polígono e activação de bairros + vias por defeito.
  • Endereço — Nominatim (online) ou substring local com unaccent em landbase.vias_alvo_sp.

8 Painel Operação

Guias: OMS, MWM, DMS, IND, SMT, ESQ (esquemático / unifilar), TMP (clima), AUD. Utilizadores: Configurações → Gerenciar utilizadores (não na barra de guias).

  • OMS — ordens e folha via REST.
  • ESQ — vistas em schematic.*; leitura e edição de nós via API; «Ir para o mapa» usa foco do nó ou equipamento GIS quando ligado.
  • TMP — Open-Meteo (SP centro), radar RainViewer opcional; não substitui alertas oficiais (INMET/CPTEC).
  • Ir para o mapa — centra e activa vista operacional (bairros/vias conforme regras).
  • Outras guias podem estar em mock — ver docs/mds/CONTEXT_STATE.md.

9 Configurações e dados de referência

Gerenciar visualização

  • Limites de zoom Leaflet para activar/desactivar Bairros e Vias; opção Sobrepor regras atuais.
  • Persistência: localStorage (tabgis_layer_zoom_cfg_v1).

Traduções

Modal espelhado para chaves config.translation (EN/PT/ES/IT); API GET /api/translations/:lang.

Glossário técnico (sem duplo sentido coloquial): chaves UI_GLOSSARY_LINEAR_NETWORK_SEGMENT, UI_GLOSSARY_POSTGIS_TOPOLOGY, UI_HELP_STACK_POSTGIS_TOPOLOGY, UI_HELP_API_TOPOLOGY — cadastro em infra/sql/02_populate_translations.sql; reaplicar o ficheiro na PostGIS após alterações e reiniciar o contentor api.

Utilizadores e ref.*

Utilizadores: GET/POST /api/users sobre security.users. Tipos de domínio: GET /api/ref/types, PUT /api/ref/types para rótulos; códigos code fixos na vista actual.

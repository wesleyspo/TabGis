TabGis — Ajuda do utilizador

Documento derivado do escopo do projecto GeoUtil / TabGis e do estado operacional da POC (docs/Escopo_Projeto_GeoUtil.md, docs/CONTEXT_STATE.md). Actualizado com as funcionalidades de interface descritas abaixo.

1. O que é o TabGis

Plataforma web para gestão e visualização de redes de utilities (energia, telecomunicações, águas, gás, etc.), no contexto académico do projecto GeoUtil. A POC actual concentra-se em mapa, basemap offline, painel de operação e integração com PostGIS / GeoServer.

2. Arranque e ambiente

  • URL recomendado: frontend servido pelo nginx na porta 8088 (same-origin para /geoserver, /tiles e /api).
  • Stack: PostGIS, GeoServer (WMS/WFS), TileServer GL (MBTiles raster), API Node (/api), MongoDB (reservado a eventos futuros).
  • Mensagens de erro na barra de estado seguem o padrão: recurso, remediação e referência a runbooks quando aplicável.

3. Topbar (barra superior)

Esquerda

  • Início — repõe a vista inicial do mapa (enquadramento depende de tela cheia vs. painel Operação aberto e do layout CC).
  • Operação — abre ou fecha o painel lateral de operação (split com o mapa).
  • Com Operação aberta pode haver opção de layout (ex.: foco no centro de controlo vs. mapa), conforme a sua configuração.

Direita

  • Estado — texto curto com feedback (carregamento, erros, confirmações); posicionado para não deslocar os menus.
  • Clima (atalho) — botão em forma de cápsula sol + nuvem à esquerda de Busca: abre o painel Operação na guia TMP (previsão e sobreposição no mapa).
  • Busca — painel em <details>: municípios e bairros (WFS), endereço (Nominatim online ou geocodificação local PostGIS).
  • Camadas — imagem de fundo (satélite online/local, GeoSampa offline), vias, limites administrativos, municípios-alvo e bairros com toggles e pills OMS/MWM/GIS/LAND.
  • Configurações (engrenagem) — idioma, Gerenciar visualização, Gerenciar utilizadores (modal, API /api/users), Tipos de domínio (ref) (modal, GET/PUT /api/ref/types), Gerenciar Traduções, Ajuda (esta página).

Só um menu entre Busca, Camadas e Configurações fica aberto de cada vez; clique fora da topbar fecha os painéis.

4. Mapa

  • Camadas vectoriais via WMS (GeoServer, workspace base_sp).
  • Clique no mapa — GetFeatureInfo onde configurado; ao clicar, os dropdowns da topbar fecham.
  • Limite UF — pode aparecer automaticamente em zoom muito afastado (lógica de zoom da aplicação).
  • Bairros vs. municípios-alvo — em zoom mais próximo, com o toggle de bairros activo, o sistema pode trocar o destaque de municípios-alvo por bairros; isto interage com os limiares configuráveis (ver secção 8).

5. Indicador de zoom (%)

Junto aos botões + / − do Leaflet aparece uma percentagem: 0 % corresponde ao zoom da última vista Início (baseline); 100 % ao detalhe máximo nativo da imagem de fundo activa (satélite online, MBTiles local ou GeoSampa offline), ou ao máximo do mapa se não houver raster activo.

Com percentagem elevada (por defeito, a partir de 50 %), a aplicação pode activar automaticamente as camadas de bairros e vias quando o nível de zoom Leaflet o permitir, para alinhar detalhe visual e vectorização.

6. Busca

Município e bairro

  • Listas alimentadas por WFS sobre municípios-alvo e bairros-alvo.
  • Ao escolher um bairro, o mapa enquadra o polígono e, por defeito, activa bairros e vias no painel Camadas, garantindo zoom mínimo adequado às vias.

Endereço ou lugar

  • Online: Nominatim (OSM), com viewbox na região de São Paulo — requer Internet no servidor/API conforme configuração.
  • Local: substring nos nomes de vias em PostGIS (landbase.vias_alvo_sp), com normalização sem acentos (extensão unaccent na base); não substitui geocodificação completa com número de porta.

7. Painel Operação

Guias na barra lateral: OMS, MWM, DMS, IND, SMT, TMP (clima), AUD. A gestão de utilizadores não está nesta barra: use Configurações → Gerenciar utilizadores.

  • OMS — listagem e folha de ordem (tarefas, reclamações) via API REST.
  • TMP — resumo tabular (Open-Meteo, SP centro) e sobreposição no mapa opcional: círculo de referência da previsão e camada de radar (RainViewer). Botão Atualizar previsão. Não substitui alertas oficiais (ex.: INMET/CPTEC).
  • Ir para o mapa — a partir de uma ordem, centra o mapa e activa vista operacional (bairros/vias; regras de zoom aplicam-se).
  • Outras guias podem estar em mock — consulte docs/CONTEXT_STATE.md.

8. Gerenciar visualização

Modal aberto a partir de Configurações → Gerenciar visualização. Permite definir:

  • Níveis de zoom (Leaflet) para activar e desactivar as camadas Bairros e Vias.
  • Sobrepor regras atuais — se ligado, estes valores substituem os limiares por defeito da aplicação; se desligado, mantém-se o comportamento «hard-coded» por defeito (valores usados apenas como referência gravada, conforme implementação).
  • Os valores são guardados no navegador (localStorage, chave técnica tabgis_layer_zoom_cfg_v1). Salvar aplica de imediato; Resetar repõe o padrão.

9. Imagens de fundo offline

  • Satélite local — MBTiles servidos pelo TileServer (/tiles/data/sp_sat/…); geração descrita nos runbooks (build_sp_satellite_mbtiles.sh).
  • GeoSampa — Offline — segundo pacote MBTiles quando disponível (geosampa_offline.mbtiles); activação verifica metadados no TileServer antes de mostrar a camada.
  • Satélite online (Esri) e camadas locais são em geral mutuamente exclusivos no toggle de fundo para evitar sobreposição.
Documentação GeoSampa offline

Funcional — gerar, reparar buracos, reiniciar TileServer, validar no mapa: GeoSampa_offline_operacao.md (no repositório: docs/GeoSampa_offline_operacao.md)

Técnica — MBTiles, variáveis de ambiente, WMS, semântica de falhas e scripts: GeoSampa_offline_tecnico.md (no repositório: docs/GeoSampa_offline_tecnico.md)

10. Gerenciar Traduções

Modal para edição espelhada de chaves config.translation (EN/PT/ES/IT). O idioma da sessão altera-se pelo selector na engrenagem; as traduções são carregadas via GET /api/translations/:lang.

11. Utilizadores e tipos ref.*

Utilizadores: modal a partir da engrenagem; lista e criação de contas em security.users (GET/POST /api/users). Perfil de acesso em evolução.

Tipos de domínio: modal que lê as tabelas ref.equipment_type, ref.network_type, ref.network_level, ref.connection_state, ref.work_order_type, ref.task_type, ref.call_type via GET /api/ref/types; guardar rótulos com PUT /api/ref/types. Os códigos code não são editáveis nesta vista.

12. Testes E2E (Playwright)

Pasta e2e/: após npm install e npx playwright install chromium, com a stack Docker a servir o frontend em :8088, execute npm test (opcional: PLAYWRIGHT_BASE_URL=…). Cobre fumo de mapa, traduções e entradas do menu Configurações.
